    12. Implantação

    Durante o desenvolvimento, o [Android Studio] (ou [gradlew installDebug]) instala a versão “debug” do aplicativo: assinada com uma chave de depuração gerada automaticamente, que habilita o depurador. Para implantá-lo, gera-se a versão “release”.

    12.1. A versão de produção do aplicativo

    1. Compile o aplicativo, especificando o endereço do servidor de produção. Em uma janela de prompt de comando aberta na pasta [rdvmedecins_kotlin]:
    1
    gradlew assembleRelease -Pserver=https://rdvmedecins.example.com

    [Gradle] compila o código [Kotlin] em “bytecode” e depois em código [Dalvik] (o formato dos arquivos [.dex], executados pela máquina virtual do [Android], o [ART]) e empacota tudo — junto com os recursos e as bibliotecas — em um arquivo APK: o formato de instalação dos aplicativos [Android]. Diferentemente do [Flutter], não há engine a embutir: a interface é renderizada pelo [Compose], uma biblioteca como qualquer outra. O arquivo resultante, [app/build/outputs/apk/release/app-release-unsigned.apk], tem alguns megabytes.

    O bloco [buildTypes { release [ ... ] }] em [app/build.gradle.kts] configura essa versão. Nele, você pode habilitar o otimizador [R8] ([optimization [ enable = true ]]): ele remove o código não utilizado das bibliotecas e encurta os nomes, o que reduz o tamanho do APK. Em seguida, é preciso instruí-lo a manter o que o serializador encontra por reflexão (as regras do [kotlinx.serialization] são fornecidas com a biblioteca) e TESTAR a versão otimizada.

    1. Assine-o. O [Android] só instala aplicativos ASSINADOS. O mais simples é usar o [Android Studio]: o menu [Build / Generate Signed App Bundle or APK] cria a chave do desenvolvedor (um arquivo “keystore” protegido por senha, que você deve guardar em segurança: todas as atualizações do aplicativo devem ser assinadas com ela) e depois compila e assina o APK. Você também pode definir a assinatura em [app/build.gradle.kts] (bloco [signingConfigs]), lendo as senhas das propriedades do [Gradle] em vez de gravá-las no código.

    2. Instale-o. Com o celular conectado ao computador (cabo USB, depuração USB ativada):

    1
    adb install app-release.apk

    Você também pode copiar o arquivo APK para o celular e abri-lo: o [Android] pedirá então que você permita a instalação de aplicativos “de fontes desconhecidas”.

    1. Para a publicação de fato:

    2. [Google Play Store] exige um “Android App Bundle” em vez de um APK: [gradlew bundleRelease], ou o mesmo menu do [Android Studio]. O Google gera os arquivos APK sob medida para cada celular;

    3. o nome e o ícone do aplicativo são configurados em [res/values/strings.xml] ([app_name]) e em [res/mipmap-*/] (menu [New / Image Asset] do [Android Studio]);
    4. [versionCode] (um inteiro) deve ser incrementado a cada publicação; [versionName] é a versão exibida;
    5. o servidor deve ser configurado para HTTPS (as senhas são transmitidas) e a linha [android:usesCleartextTraffic="true"] é removida do manifesto;
    6. o token é armazenado em [SharedPreferences], um arquivo privado do aplicativo. Para maior segurança, ele pode ser criptografado usando o “keystore” do [Android] (biblioteca [androidx.security]).

    12.2. O servidor de produção

    Em um ambiente de produção real, não se esqueça do arquivo [.env] no servidor:

    • um [JWT_SECRET] longo e aleatório;
    • um [CAPTCHA_TEST] vazio;
    • [COOKIE_SECURE=true] se o site for servido via HTTPS (e deve ser). O cliente mobile envia o cookie independentemente dessa opção: é o navegador que a aplica;
    • [TRUST_PROXY=true] se o servidor estiver atrás de um proxy ([nginx]...), para que o limite de tentativas enxergue o endereço IP real dos clientes.

    Em seguida, iniciamos o servidor compilado: [npm run build], seguido de [npm run start:prod].
